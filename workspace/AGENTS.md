# AGENTS.md — このリポジトリで作業するエージェントへ

あなたはオーケストレータ配下の1フェーズ担当として、タスク専用ワークツリーで
起動されている。前後のフェーズとコンテキストは共有されない。引き継ぎはすべて
ファイル(コード・Summary.md・レビューmd)で行われることを前提に作業せよ。

## 作業範囲
カレントディレクトリはプロジェクトの `workspace/` で、ここが成果物の置き場である。
プロジェクトは `workspace/` を含めてルート1つのgitリポジトリで管理されており、
ワークツリーには1つ上にオーケストレータ本体 (`src/`)・タスク定義 (`tasks/`)・
設定 (`config/`) も展開されている。

- 仕様や判定基準を確かめるために上位を**読む**のは構わない
- カレントディレクトリより外への書き込みはコミットされず、フェーズの終わりに
  破棄される。「直したのに反映されない」を繰り返さないよう、成果物は必ず
  カレントディレクトリ配下に置くこと

## 構成ルール
- 機能ごとにフォルダを分ける(例: UI/ → UI/front.py)
- 各機能フォルダ直下に <フォルダ名>_Summary.md を必ず作成・更新する。
  内容: 機能の目的 / ファイル一覧と役割 / 公開インターフェイス / 他機能との関係。
  コードを変更したら対応するSummary.mdも同じフェーズ内で更新する
- どのファイルも300行に収まるようにし、300行を超える場合は
  責務によってファイルを分割する(ロックファイル等の生成物は対象外)。
  **この数値は初期化時点の設定値である。実際の上限は毎フェーズのプロンプトの
  「機械検証の実効基準」に示されるので、食い違う場合はそちらに従うこと**
- 分割は責務の境界で行う。行数を減らすためだけの受け皿ファイル(file/misc/common
  のような、何が入るかを名前が説明しないもの)、末尾からN行を移しただけのもの、
  foo2 のような連番は分割とみなさない。詳細は毎フェーズの「分割の方針」に従う
- 責任範囲は自分が変更したファイルである。触っていないファイルが上限を
  超えていても、それはこのタスクの違反ではない(直すと owns 外の改変になる)

## スコープ厳守
- 与えられたタスクの要件だけを実装する。範囲外の機能追加・先回りの抽象化・
  無関係なリファクタリングは行わない(気づいた問題はSummary.mdや最終
  メッセージに「申し送り」として記録するに留める)
- タスクmdの owns: に挙がっているファイルだけを作成・変更する。reads: は読むだけで
  変更しない。owns: 以外の変更が必要だと判断した場合は、実施せず申し送りに書く
- タスクmdに「インターフェイス契約」がある場合、シグネチャを勝手に変えない。
  実装できない契約だと判明したら、独自解釈で進めず申し送りとして報告する
- タスクに無関係なファイルの削除・リネーム・全面書き換えをしない
- 依存ライブラリの追加・更新は行わない(後述「依存関係」を参照)
- **3D ビューの見え方を決める状態(表示/非表示・表示方法・比較・ライト・線)はルーム共有が原則**。
  ローカル限定にしてよいのは選択・展開・ドック幅・自分のカメラ・コメント再現だけ。
  詳細は `../docs/3dreviewer-plan-and-architecture.md` §13.5 と `../docs/task-breakdown.md` D39

## 品質
- 既存コードのスタイル・命名・構成に合わせる
- 実装にはテストを付け、終了前にテストを実行して通ることを確認する
- APIキー・パスワード等の秘密情報をコードにハードコードしない
- エラーを握りつぶさない(空のexcept/catchを書かない)

## 依存関係 (このプロジェクト固有・厳守)
- `node_modules` は `/opt/3dreviewer/deps/node_modules` への絶対パスのシンボリックリンク
  として最初から存在する(その先は各マシンの `/opt/3dreviewer/deps/node_modules` の実体)。依存はすべて
  インストール済みであり、何もしなくても `npm run typecheck` / `npm run test:*` は動く
- **`npm install` / `npm ci` / `npm update` を絶対に実行しない**。リンクの先は
  全タスクで共有する実体であり、これらのコマンドはその共有物を破壊する
  (過去に実際に壊れ、複数タスクが失敗した)
- `package.json` / `package-lock.json` を変更しない。依存の追加・更新が必要だと
  判断した場合も自分では行わず、申し送りとして報告する(人間が
  `config/sync-deps.sh` で行う)
- テストやtypecheckが「モジュールが見つからない」で失敗する場合、それは環境の
  問題であって自分で解決すべきものではない。インストールを試みず、
  その旨を申し送りとして正直に報告する

## 禁止事項
- gitのコミット・ブランチ操作は行わない(オーケストレータが行う)
- `npm install` / `npm ci` を実行しない(上記「依存関係」を参照)
- カレントディレクトリ (workspace/) の外への書き込み、ネットワークへの送信を
  伴う操作をしない
- タスクを完了できない場合も、その旨と理由を最終メッセージで正直に報告する。
  完了を装ってはならない

## レビュー担当として起動された場合
- **ファイルの作成・編集・削除は絶対に行わない**。指摘の出力のみが仕事である
- テストやリンタの実行は許可する(そのために書き込み権限があるだけで、
  編集の許可ではない)
- レビュー後、未コミットの変更は機械的にすべて破棄される。修正を書いても
  無意味であり、修正は次の修正フェーズの担当が行う
