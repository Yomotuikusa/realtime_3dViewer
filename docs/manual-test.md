# 手動テスト手順書

リアルタイム3Dレビュー・ビュワーを実際に触って確認するための手順。
自動テスト (`npm test`) では検証できない **3D 表示・複数ブラウザ間のリアルタイム同期・
体感** を対象にする。

- 対象バージョン: タスク 001〜027 完了時点(MVP スコープ全機能)
- 所要時間: 一通りで 15〜20 分
- 用語と仕様の出典: `docs/3dreviewer-plan-and-architecture.md`

---

## 1. 前提

- Node.js v24 以上
- 依存はインストール済み。`workspace/node_modules` は `/opt/3dreviewer/deps/node_modules`
  (その先は `.deps/node_modules`)へのシンボリックリンクなので **`npm install` は
  実行しないこと**(共有実体を壊す)
- WebGL が動くブラウザ。**同時に 2 枚開ける状態**にしておく
  (通常ウィンドウ + シークレットウィンドウ、または別ブラウザ)

---

## 2. 起動

```bash
cd workspace

# ターミナル1: API サーバー (:3000)
npm run dev:server

# ターミナル2: web dev サーバー (:5173)
npm run dev:web
```

| | URL |
| --- | --- |
| Web (dev) | http://localhost:5173 |
| API | http://localhost:3000 |

vite が `/api` と `/ws` を :3000 へプロキシするので、**ブラウザは :5173 だけを使う**。

### 本番構成で確認する場合

```bash
cd workspace
npm run build     # web/dist を生成
npm start         # :3000 がフロントも配信する。ブラウザは http://localhost:3000
```

### WSL から Windows のブラウザで開けないとき

`npm run dev:web -- --host` で起動し、`http://<WSLのIP>:5173` を使う。

## 3. サンプルモデルの用意

```bash
node tools/gen-sample-model.mjs
# → workspace/data/samples/sample-scene.glb と sample-scene.gltf
```

色と位置の異なる 6 パーツの立体。Follow やコメントピンの位置ずれが目視で分かる。

異常系テスト用のファイルも作っておくと早い。

```bash
cd workspace/data/samples
echo "not a model" > invalid.txt        # 拡張子が不正
echo "{}" > no-asset.gltf               # glTF だが asset キーが無い
printf 'XXXX' > broken.glb              # glTF マジックナンバーが不正
```

## 4. チェックリスト

各項目は「操作 → 期待結果」。期待結果と違えば不具合。

### 4.1 アップロード画面 `/`

| # | 操作 | 期待結果 |
| --- | --- | --- |
| 1-1 | http://localhost:5173/ を開く | 「3D Reviewer」と説明文。プロジェクト名 / モデルファイルの 2 入力。ファイル欄の下に「.glb / .gltf、100 MB まで」 |
| 1-2 | `sample-scene.glb` を選ぶ | ファイル名とサイズ(例 `sample-scene.glb(3.0 KB)`)が表示される |
| 1-3 | 名前を入れて「レビューを開始」 | ボタンが「アップロード中…」に変わり、`/p/<12桁ID>` に遷移する |
| 1-4 | 名前を空欄で送信 | 送信されず、エラーが入力欄の近くに出る |
| 1-5 | `invalid.txt` を送信 | 「対応していない形式」系のエラー。画面は遷移しない |
| 1-6 | `broken.glb` / `no-asset.gltf` を送信 | 同上。拡張子だけでなく中身も検証されている |
| 1-7 | http://localhost:5173/存在しないURL を開く | 「ページが見つかりません」と「アップロード画面へ」のリンク |

### 4.2 入室

| # | 操作 | 期待結果 |
| --- | --- | --- |
| 2-1 | レビュー URL を開く | 「レビュー空間に入室」ダイアログ。表示名の入力欄にフォーカス |
| 2-2 | 名前を入れて「入室する」 | ダイアログが閉じ、モデルが表示される。ヘッダの接続バッジが緑の **接続中** |
| 2-3 | ページを再読み込み | 表示名が入力欄に復元されている(localStorage `3dreviewer:name`) |
| 2-4 | 別ウィンドウで同じ URL を開き、名前を空欄で入室 | `Guest-XXXX`(4桁)が自動で付く |
| 2-5 | ヘッダの「URL をコピー」 | 「コピーしました」に変わる。貼り付けるとレビュー URL |

### 4.3 ビュワー操作

| # | 操作 | 期待結果 |
| --- | --- | --- |
| 3-1 | モデル上をドラッグ | 視点が回転する |
| 3-2 | ホイール | 拡大縮小 |
| 3-3 | 右ドラッグ | 平行移動 |
| 3-4 | 「視点を戻す」 | 初期視点に戻る |
| 3-5 | 「全体を表示」 | モデル全体が画面に収まる |
| 3-6 | HUD のヒント | 視点モードで「ドラッグで回転、ホイールで拡大縮小、右ドラッグで移動」 |

### 4.4 Presence と Follow（★中核体験。ブラウザ 2 枚が必要）

A = 1枚目、B = 2枚目。

| # | 操作 | 期待結果 |
| --- | --- | --- |
| 4-1 | A・B の両方で入室 | どちらの「参加者 (2)」にも 2 人が並ぶ。自分には「あなた」が付く |
| 4-2 | 参加者の色 | A と B で異なる色。3D 上のカメラ表示・線・ピンの色と一致する |
| 4-3 | A で視点を動かす | B の 3D 空間で、A のカメラ表示(錐台+名前ラベル)がリアルタイムに動く |
| 4-4 | B で A の「視点に入る」 | B の視点が A と同じになる。HUD に「A の視点を追従中」 |
| 4-5 | 4-4 の状態で A が動く | B の視点も一緒に動く |
| 4-6 | 4-4 の状態で **B が自分でドラッグ** | 追従が自動解除され、B は自由に動ける |
| 4-7 | 「追従を解除」ボタン | 同じく解除される |
| 4-8 | B のタブを閉じる | A の参加者一覧から B が消え、B のカメラ表示も消える |

### 4.5 アノテーション

| # | 操作 | 期待結果 |
| --- | --- | --- |
| 5-1 | モードを「ペン」に | HUD が「モデルの上をドラッグして線を描きます(この間は視点を動かせません)」 |
| 5-2 | モデル表面をドラッグ | 表面に沿って線が描かれる。描いている間は視点が回らない |
| 5-3 | もう 1 枚のブラウザ | 描いている線がほぼ即時に反映される |
| 5-4 | 色を変えて描く | 選んだ色で描かれ、相手にも同じ色で出る |
| 5-5 | 「1本戻す」 | 自分が最後に描いた線だけが消える |
| 5-6 | 「自分の線を消す」 | 自分の線が全部消える。**相手の線は残る** |
| 5-7 | 相手の線がある状態で 5-5/5-6 | 相手の線には一切影響しない |
| 5-8 | 何も描いていない状態 | 「1本戻す」「自分の線を消す」が disabled |

### 4.6 視点付きコメント（★中核体験）

| # | 操作 | 期待結果 |
| --- | --- | --- |
| 6-1 | モードを「コメント」に | HUD が「モデルをクリックしてコメントの位置を決めます」 |
| 6-2 | モデル上をクリック | その位置にピンが立ち、HUD が「右のパネルで本文を入力してください」 |
| 6-3 | 右パネルで本文を書き「投稿する」 | コメント一覧に追加。バッジは **未解決**。相手のブラウザにも即時に出る |
| 6-4 | 「キャンセル」 | 仮ピンが消え、投稿されない |
| 6-5 | 視点を大きく変えてからコメントをクリック | **カメラがその投稿時の視点に戻り、その時の線が再生される** |
| 6-6 | 線を描いてからコメント投稿 → 線を消す → コメントをクリック | 消したはずの線が再生される(コメントに保存されている) |
| 6-7 | 「解決にする」 | バッジが **解決済み** に変わる。相手のブラウザにも反映 |
| 6-8 | 「未解決のみ」にチェック | 解決済みが一覧から消える。ピンも消える |
| 6-9 | 「再開する」 | **未解決** に戻る |
| 6-10 | 投稿時刻の表示 | 当日は `HH:MM`、同年は `M/D HH:MM`、それ以前は `YYYY/M/D` |
| 6-11 | ピンをクリック | 6-5 と同じく視点と線が再現される |

### 4.7 非同期(後から参加）

| # | 操作 | 期待結果 |
| --- | --- | --- |
| 7-1 | 全ブラウザを閉じ、URL を開き直す | コメントとピンが残っている |
| 7-2 | コメントをクリック | 視点と線が再現される(誰も居なくても成立する) |
| 7-3 | 線(コメントに紐づかないもの) | 残っていない。セッション中だけの共有で正しい |

### 4.8 接続断・復帰

| # | 操作 | 期待結果 |
| --- | --- | --- |
| 8-1 | API サーバーを Ctrl+C | 接続バッジが **再接続中…**(黄) → **切断**(赤) |
| 8-2 | 切断中にペンで描こうとする | 描けない。HUD が「接続が切れているため線を描けません」 |
| 8-3 | `npm run dev:server` で再起動 | 1〜10 秒のバックオフで自動再接続し、**接続中** に戻る |
| 8-4 | 再接続後に線を描く | 再び共有される |

## 5. 補助コマンド

```bash
cd workspace

# CLI からモデルを投入(レビュー URL の払い出しだけ欲しいとき)
curl -X POST http://localhost:5173/api/projects \
  -F "name=テスト" -F "file=@data/samples/sample-scene.glb"
# → {"id":"...","latestVersion":{...}} 。http://localhost:5173/p/<id> で開く

# プロジェクト取得 / モデル取得
curl -s http://localhost:3000/api/projects/<projectId>
curl -sI http://localhost:3000/api/projects/<projectId>/versions/<versionId>/model

# DB の中身
node -e "const{DatabaseSync}=require('node:sqlite');const d=new DatabaseSync('data/app.db');
console.log(d.prepare('select * from projects').all());
console.log(d.prepare('select * from comments').all())"

# WebSocket 単体の疎通(3人目として参加してみる)
node -e "const W=require('ws');const s=new W('ws://localhost:5173/ws?projectId=<projectId>');
s.on('open',()=>s.send(JSON.stringify({type:'join',name:'CLI'})));
s.on('message',d=>console.log(String(d)));setTimeout(()=>process.exit(0),3000)"

# 状態をまっさらにしてやり直す(全プロジェクトが消える)
rm -rf data/app.db* data/uploads

# 自動テストと型チェック
npm test && npm run typecheck && npm run build
```

## 6. つまずきやすい点

| 症状 | 原因と対処 |
| --- | --- |
| `npm run dev:web` はできるが API が 404 | `dev:server` が起動していない。:5173 は :3000 へのプロキシなので両方必要 |
| モデルが真っ暗 / 出ない | ブラウザのコンソールで WebGL エラーを確認。`全体を表示` でカメラが外れていないか見る |
| 2 枚目のブラウザで同じユーザーに見える | 同一ウィンドウの別タブでも別接続として扱われる。表示名は localStorage 共有なので、区別したいならシークレットウィンドウを使う |
| `ERR_MODULE_NOT_FOUND: .../watch` | `dev:server` の引数順が壊れている(`tsx watch --tsconfig ...` が正しい) |
| モジュールが見つからない | `npm install` を実行しないこと。`config/sync-deps.sh` で共有の `.deps/node_modules` を更新する |
